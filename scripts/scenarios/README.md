# Scenario Scripts

These scripts are executable validation scenarios, not product architecture or
public SDK examples.

## Legacy Run Storage GUI

Run:

```sh
uv run python scripts/scenarios/legacy_run_storage_gui.py
```

The script creates synthetic legacy-system output files, records declared
legacy locators in Measurement Records storage, converts each legacy file to
normalized primary CSV, attaches each CSV to the same legacy Measurement
Records record for that run, records explicit parameter-file, setup-binding,
code-directory, and preliminary-analysis references as record-local context
attachment receipts, lists storage inventory, projects a measurement-oriented
review model, and writes a static HTML review page. The page leads with user
measurement entries and recorded context, then keeps record-local storage
artifacts plus raw storage inventory as diagnostics. The scenario also writes
the promoted Measurement Records operator-review HTML artifact so the scenario
can be compared with the reusable prototype review surface.

The scenario treats legacy system id, legacy run id, label, experiment type,
and locator values as the user-facing input. Scopecat request ids, record ids,
locator ids, and source item ids are generated by the scenario from those
legacy facts and are shown only as diagnostics. The review page presents one
measurement per legacy run; each converted primary data file is attached to
that run's generated Scopecat record, and each context attachment remains a
reference-only review fact.

Use `--workspace ./path` to keep outputs in a specific directory. Use `--open`
to open the generated HTML page in the default browser.

The scenario deliberately does not define a final GUI, adapter framework,
legacy schema, storage schema, generic existing-record import behavior,
product history, or audit-log semantics.
