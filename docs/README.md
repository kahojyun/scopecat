# Scopecat Direction

This directory is intentionally small. It records only project direction that
should remain useful as the implementation changes.

- [Project charter](project-charter.md): long-term goals, scope boundaries, and
  enduring design principles.

Implementation architecture, package inventories, completed migration plans,
and current capability lists belong in code, tests, or version control. Design
decisions that a maintainer needs while changing an implementation belong in
the docstring of the module, class, or function that owns the decision.

Add another document only when it states a long-term goal or non-goal that
cannot be explained at a more precise code boundary.
